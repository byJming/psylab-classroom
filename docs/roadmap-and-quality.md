# 路线图与质量门槛

## 1. 阶段

### Phase 0：契约与垂直切片

- 固定 Definition、Session Manifest、Result Bundle 和 CSV 规范。
- 完成 Simple RT 的说明、预检、运行、IndexedDB、导出和导入闭环。
- 建立固定随机种子样例和指标测试。

### Phase 1：课堂可用版

- 加入 Stroop、Go/No-Go、Mental Rotation。
- 完成教师预设、会话文件、批量导入、去重、错误报告和代码本。
- 实现 `open` 与 `guided` 层发布过滤；`guided` 通过参与者增强提示、确认和 debrief 记录约束运行。
- 在真实 Chrome/Edge Windows 机房环境进行小规模试用。

### Phase 2：实验库扩展

- 加入 Flanker、Simon、Visual Search、记忆扫描、Digit Span、Spatial Span 等复用度高的范式。
- 为每个实验补齐中文教学包、许可信息、样例数据和质量测试。
- 发布开源实验包贡献指南。

### Phase 3：生态扩展

- 发布实验包注册表和稳定 schema。
- 提供自托管 JATOS 适配器或其他学校内部收集适配器。
- 在明确同意、单独治理和可撤回的前提下研究参考数据集。
- 为 `controlled` 层建立部署说明、材料审查清单和导入警示，继续不将其加入公共体验馆。

## 2. 工程质量门槛

每个实验合并前必须通过：

- TypeScript 类型检查和 lint。
- Definition schema 校验。
- 固定随机种子下的 trial 数、条件比例和正确答案测试。
- Metrics 单元测试：正常、全错、无响应、失焦、重复和缺字段。
- JSON/CSV 导出再导入 round-trip 测试。
- Chrome/Edge Windows 桌面运行测试。
- 资源预加载、刷新恢复和浏览器存储不可用时的降级测试。
- 中文字体、长文案、键盘布局和色觉可用性检查。

## 3. 实验验收指标

实验包至少满足：

- 完成一次任务不需要开发者控制台。
- 正式 trial 的字段和条件可由代码本解释。
- 结果页和导出文件中的指标数值一致。
- 清洗规则不会修改或丢失原始数据。
- 失败或中断时用户能看到下一步，而不是白屏。
- 任何“参考分布”都有来源和适用限制。

## 4. 发布策略

- `alpha`：开发者和助教测试，允许 schema 变化。
- `beta`：实验可运行，但结果和指标仍需课堂验证。
- `stable`：Definition、Metrics、Result Bundle 版本冻结，允许教师用于正式课程。

实验目录页面必须显示稳定性等级，不得把 beta 实验伪装成经过验证的标准任务。

稳定性与发布层级必须同时展示：例如“`guided / beta`”表示需要增强提示和 debrief 且实现仍在验证；“`open / stable`”才可作为不带额外流程的公众或正式课堂默认实验。

## 5. 分层验收

| 层级 | 除通用质量门槛外还必须满足 |
|---|---|
| `open` | 无敏感材料；结果无个人标签；可直接退出；公众结果页包含限制说明 |
| `guided` | 参与者增强确认；扩展告知；debrief 无法跳过；课堂部署可附加教师会话确认；导出记录 debrief 状态 |
| `controlled` | 不出现在公共目录；部署文档包含参与者资格、材料审查和本地伦理责任；导入页显示受控提示 |

## 6. 开源协作

- 使用 DCO 而不是复杂的版权转让流程。
- Issue 模板区分 bug、实验方法问题、内容许可问题和功能建议。
- Pull Request 必须包含样例数据、指标测试和许可说明。
- 重大 schema 或分析规则变更采用 ADR，保留迁移说明。
- 贡献者不得提交未经许可的量表、图像、音频、词表或受限数据。

## 7. 首个公开版本的退出条件

满足以下条件才发布稳定版：

1. 至少 4 个 P0 实验完成完整数据闭环。
2. 至少 2 个真实课程场景完成试用反馈。
3. 教师可独立完成配置、分发、导入和导出。
4. 结果文件可在没有 PsyLab 运行环境的情况下被 Excel、R、Python 或 JASP 读取。
5. 没有未解决的敏感内容、版权或诊断性文案问题。
